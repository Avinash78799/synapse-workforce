# Shopify and Zendesk inspection

Status: sandbox-tested implementation; live business-vendor integrations are not verified.

This milestone adds owner-managed, tenant- and agent-scoped vendor installations, account checks and minimal record inspection. It does not connect vendor writes to the agent executor. The existing managed workspaces continue to execute fictional sandbox workflows. Registration and successful reads never enable refunds, ticket updates or vendor webhooks.

## Setup

1. In **Vendor connections**, register the account subdomain and the agent that may inspect it. Full URLs and arbitrary hosts are rejected. Shopify uses `<account>.myshopify.com`; Zendesk uses `<account>.zendesk.com`.
2. A platform operator provisions the access token in Vault KV v2, mount `secret`, field `value`, at the exact `credential_path` returned by registration. Use a protected Vault UI or secure operator tooling; do not put tokens in chat, shell command arguments, source, reports or application logs. The API must have an authenticated Vault connection and read permission for the path. The optional development Vault container is not durable production secret storage.
3. Shopify requires an installed app access token with order-read permission. The query uses Admin GraphQL API `2026-07` and rejects a response from a different API version. Older order access may require `read_all_orders`. Zendesk uses an OAuth bearer token for an agent/admin with ticket-read permission. OAuth authorization, refresh, merchant onboarding and account creation are not implemented by this panel.
4. Run **Check account access**, then inspect a numeric order/ticket ID. A read check confirms only that individual request. It does not qualify an end-to-end workflow or all resource permissions.
5. **Revoke platform access** blocks subsequent inspection calls. An in-flight read finishes before revocation commits. Revoke the upstream vendor token and remove its Vault value separately. Register again for a new scoped credential reference.

## API and controls

Session authentication and CSRF are required; all routes require the workspace owner:

| Method/path | Purpose |
| --- | --- |
| GET `/api/workspace/vendors` | List scoped installation metadata; no token values |
| POST `/api/workspace/vendors` | Register `{vendor, account, agent_id}` |
| POST `/api/workspace/vendors/{id}/check` | Check account identity/required access |
| POST `/api/workspace/vendors/{id}/inspect` | Read `{resource_id: "positive numeric ID"}` |
| DELETE `/api/workspace/vendors/{id}` | Revoke local access |

Migration `008_vendor_installations.sql` enforces tenant/agent RLS. Credential paths are generated by the server; callers cannot supply tenant IDs, token values or secret references. Reads recheck active agent status and resolve credentials without caching. Redirects and environment proxies are disabled; verified HTTPS, connection/read timeouts and a 1 MiB response cap apply. Account registration and inspection are rate limited. Failures store only stable reason codes; vendor response bodies and credentials are not audited. Resource inspection returns selected metadata without email addresses, ticket bodies or attachments. Shopify amounts retain the vendor decimal/currency representation, with no assumption of two decimal places.

## Remaining qualification

Mocked HTTP contracts and isolated PostgreSQL/Redis tests establish local behavior only. No live Shopify or Zendesk token/account was used. Next work: OAuth lifecycle, trusted customer/order/ticket bindings, policy-governed mutations with idempotency and uncertain-outcome reconciliation, native vendor webhook verification, and qualification against actual development accounts. Public onboarding also needs verified email/password recovery and member deactivation.

Official contracts: [Shopify order query](https://shopify.dev/docs/api/admin-graphql/latest/queries/order), [Shopify app access](https://shopify.dev/docs/apps/build/authentication-authorization/access-tokens), [Zendesk tickets](https://developer.zendesk.com/api-reference/ticketing/tickets/tickets/).
